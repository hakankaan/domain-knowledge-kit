# ADR-0004 — Support GitHub Copilot as a first-class agent target

**Status:** Accepted  
**Date:** 2026-07-04  
**Deciders:** Kaan Akın

## Context

DKK distributes its domain knowledge to AI coding agents, but the two supported agents were not at parity:

- **Claude Code** was the deep, first-class target — a native MCP server (14 `dkk_*` tools) registered via a committed `.mcp.json`, plus `.claude/` skills, a `dkk-domain-reviewer` subagent, six slash commands, and `settings.json` hooks (session-start priming, validate gates), all installed by `dkk init --claude` and maintained by `dkk update`.
- **GitHub Copilot** was shallow — [ADR-0002](adr-0002.md) shipped only the portable, CLI-first skills under `.github/skills/` (via `dkk init --skills`), and only two of the three skills. Copilot had no domain-context instructions file, no MCP registration, and no equivalents of the slash commands or the domain-reviewer subagent.

Copilot exposes its own well-established, VS Code-native conventions — repository custom instructions (`.github/copilot-instructions.md`), prompt files (`.github/prompts/*.prompt.md`), custom agents (`.github/agents/*.agent.md`), skills (`.github/skills/*/skill.md`), and per-workspace MCP config (`.vscode/mcp.json`). The `dkk mcp` server itself is client-agnostic and already reusable as-is. The gap was purely in generation and install plumbing, all of which was Claude-shaped.

Two design questions required resolution:

1. **How does Copilot get the agent context** given it has no session-start hook to run `dkk prime` dynamically the way Claude Code does?
2. **How does `dkk update` maintain the Copilot surface** without pushing Copilot files onto repos that only use Claude Code?

## Decision

Promote GitHub Copilot to a **first-class target at parity with Claude Code**, installed by `dkk init --copilot` (and `dkk init --all` for both). The `dkk mcp` server is unchanged and reused.

### 1. Static instructions instead of a session hook

Copilot has no hook mechanism, so DKK bakes the **static** agent contract (`primeContent()` — principles, the MCP-tool retrieval table, mutation rules, ID/naming conventions, item types, layout) into `.github/copilot-instructions.md`, inside the same marker-delimited section (`<!-- dkk:start -->` / `<!-- dkk:end -->`) used for `AGENTS.md`, so hand edits and re-runs both survive. The file points to `dkk prime` / the `dkk_prime` MCP tool for the *live* domain summary (which would otherwise go stale). `dkk update` refreshes the section, so it never drifts from the installed tool version. The `SessionStart`/validate-gate behaviors of the Claude hooks have no Copilot equivalent; the static instructions file is the accepted substitute.

### 2. A bundled `tools/dkk/copilot/` template mirroring `tools/dkk/claude/`

Six prompt files (`.github/prompts/dkk-*.prompt.md`) mirror the Claude slash commands, and a `dkk-domain-reviewer.agent.md` mirrors the Claude subagent. The portable `.github/skills/` set is completed with the missing `dkk-adr-author` skill (CLI-first, per ADR-0002's portability intent). The new template dir is added to the published `package.json` `files`.

### 3. MCP registration in both `.vscode/mcp.json` and `.mcp.json`

`dkk init --copilot` writes VS Code Copilot's native `.vscode/mcp.json` (`servers` key, `type: "stdio"`) **and** the repo-root `.mcp.json`, for the widest client coverage. Both use the same idempotent, non-clobbering merge logic that preserves other servers.

### 4. `dkk update` is adoption-gated per surface (symmetric)

`dkk update` refreshes **only the surfaces a repo has already adopted**, detected independently:

- **Claude** (`.claude/`) — a `dkk-*` skill/agent/command, a DKK hook, or DKK entries in `.claude/settings.json`.
- **Portable skills** (`.github/skills/`) — any `.github/skills/dkk-*` directory.
- **Copilot** (`.github/prompts`, `.github/agents`, `.github/copilot-instructions.md`, `.vscode/mcp.json`) — a `dkk-*` prompt/agent, a `dkk` server in `.vscode/mcp.json`, or a DKK section in `copilot-instructions.md`.

`AGENTS.md` and the repo-root `.mcp.json` are the **universal base** that every `dkk init` writes, so `update` always refreshes them. Everything else is left untouched when not adopted: a Copilot-only repo never sprouts a `.claude/` tree, a Claude-only repo never sprouts `.github/` Copilot files, and a bare `dkk init` repo gets only the base refresh. (This replaced the prior behavior where `update` unconditionally force-installed the Claude surface regardless of opt-in.)

## Consequences

### Positive

- **Parity.** Copilot users get the same domain-aware experience as Claude Code users: MCP tools, ready-made prompts, a domain-reviewer agent, and always-present domain context.
- **One command.** `dkk init --copilot` (or `--all`) installs the whole surface; `dkk update` keeps it current, reusing the existing artifact diff/sweep machinery.
- **No server duplication.** The single client-agnostic `dkk mcp` server serves every client; only the registration file differs.
- **Non-invasive updates.** The opt-in detection means existing Claude-only repos are unaffected by the new behavior.

### Negative

- **Static-context staleness.** The domain summary is not embedded (only the stable contract is), so Copilot users must run `dkk prime` / call `dkk_prime` for the live model. This is a deliberate trade-off against a hook mechanism Copilot doesn't offer.
- **Template maintenance in lockstep.** The Copilot prompts, agent, and skills must be kept in sync with their Claude counterparts and with the `dkk` CLI/MCP surface when it changes.
- **No validate gates.** Without hooks, Copilot cannot enforce the post-edit / stop validation gates that Claude Code does; the model can still drift within a Copilot session until the user runs `dkk validate` / `dkk render`.

## Alternatives Considered

- **Ship only the portable skills (status quo from ADR-0002).** Rejected: skills alone give Copilot neither the MCP tools nor the always-present domain context, so Copilot stayed a second-class citizen.
- **Rely on `AGENTS.md` for Copilot.** Newer Copilot reads `AGENTS.md`, but a first-class integration wants Copilot's native `.github/copilot-instructions.md`, prompt files, and `.vscode/mcp.json` — the tool-specific surfaces users expect.
- **Force-install every surface on `dkk update`** (extending the prior unconditional-Claude behavior to Copilot). Rejected: it would surprise Claude-only repos with unwanted `.github/`/`.vscode/` files and Copilot-only repos with an unwanted `.claude/` tree. Per-surface opt-in detection is symmetric and least-surprising.
