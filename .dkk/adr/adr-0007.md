# ADR-0007 — Treat ADRs as first-class model members

## Context

Every other item type in a Domain Knowledge Pack is guarded end to end: a schema validates it, the loader reports what it cannot read, `render` gives it a page, `stats` notices when it rots, and the CLI owns its whole lifecycle. ADRs had creation (`dkk new adr`) and nothing else. The gap showed up as five distinct classes of problem.

**The ADR file was the only part of the pack with no load-time guard.**

- `dkk new adr "Use Redis: cache layer"` interpolated the title into YAML unquoted, producing invalid frontmatter. Because the loader parses every ADR, that one file took down `validate`, `render`, `search` and `show` alike, with an error naming a line number in no particular file.
- Any malformed ADR did the same: the YAML exception escaped `loadDomainModel` uncaught.
- The loader keys ADRs by their frontmatter `id`, while `locate`, `rm`, `rename` and the renderer all derive the path from it. A file named `adr-0002.md` declaring `id: adr-0009` validated clean, and then `dkk locate adr-0009` failed. Two files claiming one id silently dropped a whole decision from the model.
- `nextAdrNumber` scanned filenames only, so it would happily mint an id a mis-numbered file already held.

**Reading a decision returned a blob.** The parser stored only a Markdown-stripped copy of the body, so `dkk show adr-0006` — and `dkk_show`, the primary way an agent reads a decision — emitted headings, lists and tables flattened into one YAML scalar. *Context*, *Decision* and *Consequences* were indistinguishable. Search made it worse: the excerpt was always the first 200 characters of the text column, which for an ADR meant the title, status and deciders repeated twice before any prose.

**Bidirectional linking was documented as enforced and wasn't.** `adr-guide.md` said so; the validator only checked that each side *resolved*. A `domain_refs` entry with no matching `adr_refs` is invisible to the rendered docs, `dkk story`, and every item-side read — which is where people actually look. Nothing wrote both halves either: `dkk new adr --domain-refs` set the ADR side and left N item files to hand-edit, the step the authoring workflow most often skipped.

**Nothing measured decision rot.** Graph orphan detection explicitly excluded ADR nodes, so the item type where staleness matters most had no staleness signal. This repo — six ADRs, zero links — reported "No orphaned items found! All clear."

**And the surrounding surface disagreed with itself.** Status lived in the frontmatter *and* as a `**Status:**` line in the body, with nothing keeping them in sync. `render` produced no ADR page at all, so a pack that is mostly decisions rendered to empty docs. The schema was six fields with `additionalProperties: false` and no extension escape hatch, and its status enum had no `rejected` — a declined proposal had to be filed as `deprecated`, which asserts a history that never happened. `.dkk/adr/README.md` documented a filename convention (`NNNN-short-title.md`) and a frontmatter-free template that the loader would reject.

## Decision

**Give ADRs the same treatment every other item type already gets**, across five areas.

**Integrity.** Frontmatter is serialised through the YAML writer instead of string interpolation, so no title can produce an invalid file. `parseAdrFile` never throws — it returns a typed failure the loader collects into `model.adrIssues`, and the validator reports each against its path. Two new validator rules: `id` must match the filename, and no two ADRs may claim one id. `nextAdrNumber` considers both filenames and declared ids. One `isAdrFile` predicate now decides what counts as an ADR, so the loader and the per-file validator can no longer disagree — they did: the loader skipped `README.md`, the edit hook did not.

**Retrieval.** The body is stored verbatim and split into its level-2 sections. `dkk show <adr>` and `dkk_show` return the Markdown intact plus the section names; `--section decision` (prefix-matching) returns one part. A separate `adrSearchText` produces the flattened, boilerplate-free copy for the index — the H1 that repeats the title and the frontmatter echo are stripped, since both are already indexed as their own columns. Excerpts are centred on the match. `status` becomes a real FTS column, so `--status accepted` is an exact filter on `list`, `search`, and their MCP equivalents.

**Lifecycle.** A `dkk adr` command group owns everything after creation: `status` (validating the transition and updating every copy in the file), `link`/`unlink` (writing **both** halves), `decisions`, and `audit`. `rejected` joins the status enum. Supersession records `supersedes` on the new ADR as well as `superseded_by` on the old, so the chain is answerable from both ends. The body skeleton moves into `adr.md.hbs`, overridable per-project from `.dkk/templates/`, and gains the *Alternatives Considered* section the authoring skill always asked for. It no longer restates status or date: frontmatter is the single copy.

**Linking and health.** The validator warns on one-way links, naming the `dkk adr link` command that fixes them. `dkk adr audit` reports unlinked decisions, stalled proposals, overdue `review_by`, one-way links, and broken chains; `dkk stats` and `dkk_stats` surface the unlinked count. `domain_refs` may now target a context, actor, or flow — plenty of decisions govern one of those rather than a single item — and each of those gained a reciprocal `adr_refs`.

**Answering the actual question.** `dkk_decisions` / `dkk adr decisions` take an item id or a source path and return every bearing decision with its *provenance* (the item names it, it names the item, it governs the context, or its `code_refs` bind the file) plus which ids are in effect after following supersession. ADRs gained `code_refs` so a decision can bind the code it governs directly, and `dkk drift --file` prefers those over the context-inferred guess.

The schema also gains `tags`, `links`, `review_by`, and an `x-` extension namespace, so a team can carry its own metadata without patching DKK — while a typo like `tag:` is still rejected.

## Alternatives Considered

**Leave the body stripped and add a separate `dkk adr body` command.** Rejected: the problem is that the *default* read is lossy. Every consumer — CLI, MCP, renderer — would have had to learn to call the second thing, and the one that mattered most (an agent calling `dkk_show`) is the one least likely to.

**Enforce link reciprocity as an error.** Rejected: the model is coherent with a one-way link, and one-sidedness is the normal state halfway through authoring a change. An error would make the validator fail on work in progress. A warning that names the exact fixing command gets the same result without blocking.

**Auto-repair one-way links during `render`.** Rejected: `render` is a read-and-generate step, and having it silently mutate hand-authored YAML violates the rule that structural changes go through explicit CLI commands. `dkk adr link` is the explicit version of the same repair.

**Copy ADR prose into the generated docs.** Rejected: a second copy of the text is a second copy to drift. The decision log links to the source files in `.dkk/adr/` instead.

**Keep numbering from filenames alone and make id/filename mismatch a warning.** Rejected: the mismatch is not cosmetic. It silently breaks every path-resolving command, and the failure surfaces far from the cause.

## Consequences

**Easier.** "What has already been decided about this?" is one call that accounts for supersession, instead of three calls and a manual read-through. An agent can read just the *Decision* section instead of the whole document. Creating an ADR with `--domain-refs` links both halves, so the step most often skipped is no longer a step. Decision rot is visible from `stats`, `audit`, and a CI gate.

**Harder, deliberately.** An ADR whose `id` disagrees with its filename now fails validation — this will surface pre-existing mismatches in packs that have them, which is the point. Renaming the file (or fixing the id) is the fix.

**Migration.** Everything added is optional and additive: existing ADRs validate unchanged. Two behaviours shift for existing packs — one-way links start emitting warnings, and a `README.md` in `.dkk/adr/` is no longer schema-checked as a decision. ADRs that still carry a `**Status:**` line in the body keep working; `dkk adr status` updates it in place rather than requiring its removal.

**Cost.** The ADR feature is now its own vertical slice (`src/features/adr/`) with six modules, and the pipeline slice imports from it for the reciprocity lint. That direction — pipeline depending on a feature slice — is new, and worth watching if more of them appear.
